# UX-005 — Hostel Allocation (Disposition: NEEDS_DECISION → product clarification resolved as "request-to-admin" model)

## Original Finding (audit §30, §39 Q3)
The audit flagged `/hostel-manager/allocation` as pairing an honest "admin does this"
fallback card with a *dead* drag grid that structurally could never fill
(no rooms API). Two intended models exist:
1. Direct manager drag-assign — requires a scoped read-only rooms API + request-approve flow (advanced).
2. Request-to-admin — manager sees read-only occupancy and files a reallocation request (minimal).

## Investigation (this session)
- `src/app/(approver)/hostel-manager/allocation/page.tsx` on disk is **already in model 2**:
  - Renders `HostelAdminFallback` (feature="Bed allocation", reason, adminHref="/admin/students").
  - `PermissionScopeHint` tone="locked" states the read-only rule.
  - `SmartCrossLinkChip`s to `/hostel-manager/rooms` and `/hostel-manager/residents` (the read-only record pages that DO exist).
  - No dead drag grid — the grid the audit referenced was removed or was never on disk at this commit.
- The page is a *complete, honest* "request-to-admin" surface: it tells the user
  what they can see, what they cannot do, and how to take the action (open
  admin roster). It does NOT pair a broken affordance with an honest card.

## Disposition
**Already resolved on disk (model 2 is the shipped behavior).**
The advanced model 1 (scoped rooms API + manager request-approval flow) is a
product decision that requires:
- A backend `GET /api/hostel-manager/rooms?block=X` scoped read-only endpoint.
- A `POST /api/hostel-manager/allocation-requests` write endpoint (admin approves).
- A manager-side request form + admin-side approval queue.
- Product sign-off that hostel managers are allowed to *propose* reallocations
  (today they are strictly read-only for beds).

This is recorded as a **P2 product opportunity**, not a defect. The current
page is the correct UX for the read-only operating model. No code change needed
to close the finding; the advanced model is deferred pending the product
decision.

## Verification
- `npm run typecheck` PASS, `npm run build` PASS on main.
- No dead drag grid in the file; no unbacked affordance.
